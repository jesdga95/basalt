# 고정 호스트 데이터 풀

`--host-pool-gib N`은 모델을 읽기 전에 하나의 물리 호스트 영역을 확보하고 모든 페이지를 채운다. 전체 영역의 resident lock 성공을 요구하므로 외부 컨트롤러가 swap 설정을 바꿔도 작업 풀이 내려가지 않는다. Linux에서는 풀 크기를 허용하는 memlock 한도를 설정해야 한다. 주소 공간만 예약하거나 설정값만 바꾸는 기능이 아니다. 확보가 실패하면 READY 전에 기동을 거절하며 두 번째 큰 RAM 영역으로 우회하지 않는다.

현재 지원 범위는 단일 GPU·단일 실행 슬롯의 서버다. 체크포인트와 대화 파일 계층이 켜져 있어야 한다. 전문가 영역, CUDA pinned host 버퍼, 대화 K/V 스냅샷, 체크포인트의 큰 바이트 버퍼, prefill의 CPU 텐서와 파일 입출력 버퍼가 같은 풀을 사용한다. 해제는 풀의 빈 공간으로 돌아가고 인접 영역은 합쳐진다. CUDA 그래프의 장치 주소·가중치 형식·커널 산술은 바꾸지 않는다.

## 용량과 대피

시작 시 cgroup 할당 예산과 페이지 테이블·드라이버 기록의 기존 계산을 대조한다. OS의 MemAvailable 추정치를 실제 확보 성공으로 취급하지 않는다. 전체 영역의 resident lock과 prefault를 완료한 뒤 풀을 공개한다. 각 할당은 페이지 단위로 계상하고 그 범위만 CUDA에 등록한다. 반환 시 등록을 해제하고 같은 풀에 돌려준다. 아직 쓰지 않는 풀 공간은 물리 RAM에 남으며 GPU 가상 주소 매핑을 만들지 않는다. 확보한 풀을 재사용할 때는 그 빈 공간을 기준으로 판단하며 이미 확보한 메모리에 물리 여유 하한을 다시 적용하지 않는다.

캐시의 개수·바이트 한도 또는 풀의 공간이 부족하면 비활성 대화를 파일로 저장한다. 풀 모드의 저장은 이미 가진 스냅샷 한 개를 동기적으로 넘기므로 쓰기 대기열을 위해 큰 복사본을 추가하지 않는다. 기존 비동기 큐의 크기보다 큰 스냅샷도 한 개씩 저장할 수 있다. 저장 실패 시 버퍼를 유지하고 해당 요청을 실패시키며 다른 RAM 할당으로 우회하지 않는다. 디스크 읽기 실패가 메모리 부족 때문이면 저장 파일은 보존한다. 디스크 입출력의 작업 버퍼는 파일 계층을 열 때 풀에서 미리 확보한다.

원래 모델 파일이 있는 차가운 전문가는 기존 파일 계층을 사용한다. 활성 필수 작업 공간은 파일로 무조건 내릴 수 있는 캐시와 구별한다. 지원하는 최대 문맥과 prefill 청크에 필요한 작업 공간이 풀에 들어가야 한다.

전문가를 RAM 슬롯으로 새로 복사할 때 풀 모드는 파일의 mmap 바이트를 복사하지 않는다. 파일을 unbuffered로 읽으며, 풀에서 미리 확보한 정렬 버퍼 하나를 직렬 재사용한다. 정렬되지 않은 전문가 경계와 파일 끝의 짧은 읽기도 같은 버퍼에서 처리한다. 이 경로의 unbuffered 열기나 버퍼 확보가 실패하면 파일 캐시 복사로 우회하지 않는다.

풀 모드에서 직접 mmap 전문가를 계산하는 경로는 2GiB 읽기 창마다 Linux 파일 페이지를 반환하고 요청 종료 때도 남은 페이지를 반환한다. 전문가 선행 읽기는 사용하지 않는다. 가상 주소와 원본 바이트는 유지하므로 작업 중 보관한 포인터는 다시 접근할 때 같은 내용을 읽는다. 이 반환은 RAM 상주 복사본이나 고정 풀을 해제하지 않으며 커널 산술도 바꾸지 않는다.

## 전체 프로세스 상한

이 옵션의 N은 **호스트 데이터 풀 크기**다. 작은 제어 객체, 요청 문자열, Python/API 프로세스, CUDA 라이브러리 내부 메모리와 OS 파일 캐시는 풀 밖에 있다. 따라서 컨테이너 전체 상한이 N이면 데이터 풀도 N으로 잡아서는 안 된다. 전체 상한에는 이 실제 운영 비용을 포함하며, 운영에서 확인한 크기와 미확인 부분을 구별한다. 풀 크기만으로 호스트 전체 OOM 방지나 모든 파일 읽기 제거를 보장하지 않는다.

## 정밀도 검증

메모리의 위치와 소유권을 바꾸는 기능이며 저장하는 바이트나 커널 계산은 바꾸지 않는다. 자동 VRAM 크기 결정은 등록 비용에 따라 배치가 달라질 수 있으므로 greedy 비교 시 전문가 배치도 대조한다. CPU 검사는 용량 경계·정렬·동시 재사용·파일 저장 후 복원·실패 시 원본 보존을 확인한다. GPU 검사는 실제 prefault·등록·부분 영역 DMA·용량 초과 거절·재사용을 확인한다. 모델 검증에서는 C1·262K 입력·도구·이미지·캐시 및 파일 복원, 실제 메모리 상주와 풀이 더 커지지 않는지를 함께 측정한다.
