# 0.5.7

TODO date. Taken from `main`. Build from source: [building](../building.md), or take a release archive ([platforms](../platforms.md#release-archives)). A breaking release for every config that names more than one card: three settings replace each model's own multi-GPU logic, and `gpu: auto` is gone. The `.basalt` format stays version 2 and the config stays version 2.

## Highlights

- **Three settings say what several cards do.** `gpu` names the cards, `gpu-mode` (`peer`, `split` or `tensor`) what they do together, `gpu-share` their proportions. The engine no longer prices mechanisms, picks a main card or leaves a card idle on its own: your mode decides, and a mode the model cannot run, or a card that would hold nothing, is refused with the reason before the load. The same three names work in the server config, `basalt`, `basalt-bench` and `basalt-probe`. [GPUs](../configuration/gpus.md)
- **One shared layer for every model.** Cards, shares, placement, refusals and the start lines are shared code; a model fills a small contract per mode (`model::PeerHooks`, `model::SplitHooks`) and is checked against one card with `--diag-gpu-check`. [design](../design/multi-gpu.md)
- **Qwen3.8-27B:** `peer` reads a 64K prompt 17% faster than one card (7,410 against 6,336 tok/s) and `split` holds the later layers, both with the tokens of one card. `--kv nvfp4` refuses a second card in either mode.
- **Inkling 2 Mini peers.** `gpu-mode peer` puts the hottest experts that spilled from the main card in the second card's VRAM: with 1,572 experts spilled a 16K prompt reads 7,445 against 6,234 tok/s and conversation decodes 290 against 117. It helps only when experts spill beyond what the elastic copies cover; at default settings one card is fastest up to 1M tokens, and a split is about 25% slower than one card there. [Inkling](../models/inkling2.md#two-cards)
- **Qwen3.8-Flash-Next, DeepSeek-V4.1-Flash and Hy4-flash** keep their expert peers (`gpu-mode peer`) with no speed loss against 0.5.6 (Flash-Next 64K prefill 9,823 against 9,835 tok/s), and Flash-Next's layer split (`gpu-mode split`) takes unlike cards and up to eight.
- **An unused card is no longer a mystery.** With `gpu` unset and more cards visible, every model warns once at start, in the CLI, the server and the bench: `GPU 1 (RTX 5060 Ti) unused; to use more cards set gpu (0,1 or all) and gpu-mode`.

## Several GPUs

- `gpu` takes a number, a list (the first is the main card) or `all` (every visible card in order). `gpu-mode` is required with two or more cards and an error with one. `gpu-share` is one positive number per card in the order of `gpu`; by default a split's cut and a peer's experts follow free VRAM and a peer's prompt layers follow memory bandwidth.
- Each model states the modes it runs (`gpu_modes()`): Flash-Next peer (up to four cards) and split (up to eight); DeepSeek and Hy4-flash peer; Qwen3.8-27B and Inkling 2 Mini peer and split on two cards. `tensor` is reserved and refused everywhere. [table](../configuration/gpus.md#modes)
- Sm_89 cards stay peers in a `-DPEER_ADA=ON` build (Flash-Next); the main card must be sm_120, and split refuses sm_89.
- **Removed:** the pricing that chose a mode (`plan_multi_gpu`, the alike and unlike card rules, the 27B's per-read stage price and its layer stage rule, Flash-Next's layer plan by SMs and clock), `gpu auto`, `--diag-split-at` and `--no-peer-prefill`. A peer now always reads its experts' rows of a prompt; `gpu 0` keeps a prompt on the main card.
- **Diagnostics:** `--diag-gpu-cut L` (one cut flag for every model, replaces `--diag-split-at`), `--diag-gpu-check` with `--diag-gpu-trace` and `--diag-gpu-ref` (a mode against one card: bitwise steps, greedy identity, KLD, top-1), `--diag-gpu-same`, and for Flash-Next `--diag-main-card-bits` (the other cards run the main card's cuBLAS algorithms, so prompt stages and a split are bitwise) and `--diag-fixed-experts` (a prompt's experts all run on the GPU and a window's verifiers see none in VRAM, so two placements of the same experts compute the same rows). [diagnostics](../configuration/diagnostics.md)
- **Quality:** Flash-Next peer BF16 KLD 0.06174 against 0.06221 on one card, top-1 91.84% against 91.80% (100 chunks). A peer's prompt differs from one card's at summation-order rounding (about 0.01 KLD on `--diag-gpu-check`, the same as any reordering of the experts' sum). [precision](../precision/qwen38-flash-next.md#several-cards)
- **`basalt-bench --community`** takes the user's cards and mode like any run and records them in the row's `engine_args`; the community gate accepts `--gpu-mode` and `--gpu-share` there.
- The server's expert hit rate counts an Inkling lookup served by the second card as on a GPU, no longer as a miss.

## Upgrading

`gpu: auto`, a `gpu` list without a `gpu-mode`, and the two removed flags are errors, with no transition release. The error for a bad `gpu` or `gpu-mode` lists the valid forms and names the doc page, for example `gpu "auto": expected a card number like 0, a list like 0,1 (the first is the main card), or all; see docs/configuration/gpus.md` and `gpu 0,1 names 2 cards: set gpu-mode to peer, split or tensor; see docs/configuration/gpus.md`. A removed flag is the normal unknown-argument error.

Before and after in the config (each entry of `models`, or the `server` section):

| 0.5.6 | 0.5.7 |
| --- | --- |
| `"gpu": "auto"`, Flash-Next, DeepSeek or Hy4-flash on two cards | `"gpu": "all", "gpu-mode": "peer"` |
| `"gpu": "auto"`, Qwen3.8-27B (it read long prompts on the second card) | `"gpu": "all", "gpu-mode": "peer"`, or `"gpu": "0"` for the main card alone |
| `"gpu": "auto"`, Qwen3.8-27B that did not fit one card (the layer stage) | `"gpu": "all", "gpu-mode": "split"` |
| `"gpu": "auto"`, Inkling 2 Mini (a split when it paid, else the main card alone) | `"gpu": "0"` where the main card holds the model; `"gpu": "all", "gpu-mode": "split"` for a held-back card, `"peer"` for spilled experts |
| `"gpu": "auto"`, Flash-Next where the layer split was picked (matched cards) | `"gpu": "all", "gpu-mode": "split"` |
| `"gpu": "0,1"` | `"gpu": "0,1", "gpu-mode": "peer"` |
| `"gpu": "1,0"` (the second card as main) | `"gpu": "1,0", "gpu-mode": "peer"` |
| `"gpu": "0"` | unchanged, and silent: naming a card is a choice |
| `gpu` unset | unchanged; one warning names the other visible cards |

Flags and keys:

- `--gpu auto` is `--gpu all --gpu-mode peer` (or `split`); `--gpu 0,1` needs `--gpu-mode`.
- `--diag-split-at N` is `--diag-gpu-cut N` with `--gpu-mode split`.
- `--no-peer-prefill` is gone: a peer always reads its share of a prompt; `--gpu 0` keeps the prompt on the main card.
- `basalt-probe` and `basalt-bench` take `--gpu-mode` and `--gpu-share` beside `--gpu`.
- A cut of a split now follows `gpu-share` (free VRAM by default) in place of a priced search: a split that fits one card runs only when `gpu-mode split` says so.
- The expert counts the console reads for Inkling count the second card's lookups as hits.
