# 0.2.1

2026-11-03. Taken from `main`. Build from source: [building](../building.md). The `.basalt` format is unchanged. This release changes what a client on another machine may name as an image: read [Upgrading](#upgrading) first.

## Highlights

- Image sources follow where a request comes from. A request from this machine may name any path or URL, with no configuration. A request from anywhere else gets `data:` URLs, plus the hosts named with `--image-url-host` and the directories named with `--image-dir`. The server used to fetch any URL and read any path for any client. [image sources](../configuration/image-sources.md) (design @giveen)
- Quality is measured against full precision: a llama.cpp BF16 reference of the original model. On the same Q8_0 weights Basalt scores KLD 0.0200 and llama.cpp 0.0325. The NVFP4 prompt path's 4-bit activations, which the standard gate does not reach, are now measured on long prompts: about 0.002 KLD at 2K-token prompts, unresolved at 8K, for 17 to 19% faster prefill. [quality](../precision/quality.md)
- A `Qwen3.8-FN-NVFP4-DQ8` pack joins the default `-DQ6_K` on Hugging Face: the same NVFP4 experts with Q8_0 dense projections, lower KLD (0.0561 against 0.0624), about 7% slower on prose. [isolated costs](../precision/qwen38-flash-next.md#measured-costs)

## Upgrading

1. Rebuild: [building](../building.md).
2. A client on another machine that names an image by URL or path gets a 400 until its host or directory is allowed, or it sends a `data:` URL. A client on this machine that reaches the server by its LAN address or name, or through a forwarding proxy, counts as another machine.
3. Every client: an image is at most 32 MiB and 64 megapixels, a `data:` URL must be base64, and EPS, ICO and JPEG 2000 are refused.
4. Behind a proxy or a gateway on the same machine that adds no forwarding header, set `--image-remote-only`: such a proxy's clients otherwise count as this machine.
5. `basalt-bench --community` refuses a submitter name with spaces, or over 40 characters, as the row check does.

## Recent

Changes from 2026-11-01 to 2026-11-03.

### New

- `--image-url-host`, `--image-dir`, `--image-remote-only` (above).
- `--expert-profile FILE` names the profile a start places, so an installed engine does not depend on its source tree (@xyehya).
- A JSON format sent with tools under `tool_choice` auto: the answer is tool calls or the JSON value; it was a 400.
- The bench JSON reports the VRAM tier's hit rate (@giveen).
- Community rows for 2x and 4x RTX 5080 (@Hazelhof) and RTX 5080 IQ3_S (@Cosmin-Local-Ai).

### Faster

Commit-level, not benchmark results.

- A long prompt's KV hands the experts it moves off the main card to the peer, through the prompt split's loan on a solo request.
- The two-stage Q6_K head skips the rows whose picks are discarded (@xyehya).
- The lazy L2 prefetch also takes the next layer's FFN read matrices (@kaushikvira, @xyehya).
- CPU expert rows: AVX-VNNI for IQ3_S and IQ2_S grid indices, IQ4_NL down and Q2_0 (@xyehya); AVX-VNNI-INT8 and one-pass widths 5 to 8 for NVFP4 (@giveen).
- URL fetches and image decoding run outside the request turn, so a slow source no longer holds up other requests.

### Changed

- Output can change. The two-stage Q6_K head rescores every row above its column's bound: greedy text depended on the verify window width, and `--spec` 7 and 8 differed from 1 to 6 (@xyehya). Below 160 SMs, windows of up to eight rows run the mid chain, so a row's last bits no longer depend on the window width (@xyehya). The prompt CPU share takes experts by the cache's table, so the same prompt on the same pinned tiers puts the same experts on the CPU (@xyehya). [precision](../precision/qwen38-flash-next.md)
- Without a stall reading (Windows), RAM below the RAM guard is critical only after 10 s.
- The stored conversation's folders and files are owner-only on Linux (@xyehya).
- The layer-split device check's errors start `CUDAn:`.
- Removed code nothing could reach: the remote-expert tier, its placement and reduction options and kernels, and the decode loop's non-chain tail (@xyehya).

### Fixed

- Decode stalled after a few tokens with both cards at full use, when the cache's copy could not be page-locked (Linux under WSL, native Windows) (@G-3-N-O).
- A reply's last window commits no row past the last token sent, so a chat continuation no longer falls back to an old checkpoint or a full re-read (@xyehya).
- A tool whose parameters are a `oneOf` or `anyOf` union gets its parameters (@hagudelom). Tool-call text quoted inside a string argument stays in the string (@giveen).
- `--open` opens the page once the model is ready, and not at all if the load fails.
- A wrong-bytes read in one optimized CUDA build: byte reads out of packed values go by shift, in every format.
- Batch windows on the zero-doorbell graph take the one hand-off, so `--parallel 2` and up no longer time out at layer 0 (@beastrobin).
- A release ends bounded device waits at once, and an engine ending after a failed release skips the CUDA teardown that would wait forever.
- The split query gate's fallback waits for the gate (@xyehya). The RAM home report counts net savings (@xyehya).
- The vision sidecar is found as `basalt-vision.exe` on Windows (@f1zz1ec0ke).
- A last-pair tokenizer merge no longer aborts on builds with range checks.
- A missing expert profile is named with the path looked up.
- A malformed `data:` URL or a non-object Anthropic `source` no longer crashes the handler.
- The version in the bench JSON and start lines matches the release.
