# 0.3.1

2026-11-08. Taken from `main`. Build from source: [building](../building.md). Read [Upgrading](#upgrading) first: a few flags change. The `.basalt` format stays version 2; `experts.layout` v7 is a section version.

## Highlights

- DeepSeek's attention caches are FP8 and FP4: 920 bytes per position instead of 3,200, a 1M context's caches 0.97 GiB instead of 3.20. `--kv fp8|fp16` chooses. [precision](../precision/deepseek41.md#where-each-stage-rounds)
- DeepSeek drafts in every `--parallel` slot, from one shared drafter. [DeepSeek-V4.1](../models/deepseek41.md#parallel-slots)
- One shared prompt path for the peer card (`prefill::PeerShare`) serves both models. DeepSeek on two cards, cold, 400 W + 180 W: 2,048-token read 502 to 622 tok/s, 16,384 tokens 1,980 to 2,173, 65,536 tokens 2,733 to 2,805, decode unchanged.
- DeepSeek's expert placement follows the machine's total RAM, so a start no longer lands on either side of the homes-or-copies choice with the page cache.
- DeepSeek decodes faster: sparse MQA's code size, the indexer's top-k, the compressor and router kernels. Cold, seed 42, 400 W + 180 W: struct 146 to 151 tok/s, prose 84 to 87, conversation 78.5 to 80.
- New packs: Flash-Next `UD-IQ1_S` (a layer with its own up type, `experts.layout` v7) and `UD-IQ4_XS`, DeepSeek `UD-IQ2_XXS`; Q5_K and Q6_K expert layers join the glue path (#264) and IQ4_XS gate/up rows too (#272, @michmill1970); Q2_K and Q3_K experts run on every path.
- The model file is read in place: nothing is unpacked into `~/.cache/basalt`. The engine's `--vision` encodes in the engine and `--vision-external` takes a sidecar's embeddings.
- `--kv-resident` works with `--batch` and `--parallel`: every slot streams its own K/V (#186, @f1zz1ec0ke).
- One RAM reserve (`--ram-reserve-mib`) and RAM guard for every model, and experts on the SSD said everywhere.

## Upgrading

1. Rebuild: [building](../building.md).
2. **`--peer-prefill-rows N` is gone.** `--no-peer-prefill` (config key `no-peer-prefill: true`) turns the peer card's prompt share off; it is on otherwise.
3. **The engine's `--vision-mmproj PATH` is gone.** The engine takes `--vision` (encode in the engine, from the pack's `vision/mmproj`) or `--vision-external`. The server's `--vision dynamic|cpu|N` is unchanged and passes them itself.
4. **A pack with `experts.layout` v7 needs 0.3.1.** Only `UD-IQ1_S` has one; older engines refuse it with their update message. Every other pack keeps running on older engines.
5. **Conversations stored on disk miss once**: the cache key changed with the vision flags, and DeepSeek's stored caches in the other `--kv` format are read again from their tokens.
6. **`--kv` takes different values per model.** DeepSeek: `fp8` (default) or `fp16`; Flash-Next: `fp16` (default), `int8`, `q4_0`, `k8v4`. Any other value is refused at the flags.
7. **`--ram-reserve-mib` (default 2048) replaces the RAM floors**, and `--ram-reserve-mib 0` turns the guard off. [memory floors](../running.md#memory-floors)
8. `~/.cache/basalt/<id>` keeps only `engine.log` and the conversation cache; an earlier `tokenizer/` folder and `vision/mmproj.gguf` (886 MiB for Flash-Next) can be deleted.

## Memory, start and serving

- **Experts on the SSD are said everywhere.** Any expert only the file holds gives one engine warning, the same for every
  model: `N experts on SSD (X GiB) · free X GiB RAM`, plus the model's other fixes where it has them, such as `--gpu 0,1`.
  The server console repeats it, `/metrics` carries `engine.spill` (`experts`, `total`, `bytes`; `null` when nothing
  spilled) and each request's `ssd_share`, and the stats page turns its Experts block amber with an SSD tier.
  [memory floors](../running.md#memory-floors)
- **One RAM reserve for every model.** `--ram-reserve-mib` (default 2048) is the RAM left free for the rest of the system; the
  old floors (5% of RAM, fixed late memory, the file cache minimum, DeepSeek's fixed 16 GiB) are gone. DeepSeek allocates its
  prompt and image host buffers at start and its RAM tier takes the rest less the reserve and the driver's page tracking, so
  one place short no longer sends about 12 more experts per layer to the file. Its prompt ring of second-card and file reads
  is capped instead of growing with the experts left in the file, and a prompt no longer stages a whole chunk's embeddings
  and Engram rows. Flash-Next allocates its checkpoint blocks and holds the RAM of its page-locked prompt buffers before its
  RAM copy, which then sizes the same way; its estimate of what it takes later is gone. [memory floors](../running.md#memory-floors)
- **One RAM guard for every model.** The serving RAM guard starts in the shared serve path and holds the reserve, so DeepSeek
  now sheds parked conversations, holds new requests and stops one at critical RAM as Flash-Next does. `--ram-reserve-mib 0`
  turns it off, for machines where it stopped requests that would have fit (reported by @pngen).
  [memory floors](../running.md#memory-floors)
- **Default context 8,192 for every model.** Flash-Next's was 4,096 and DeepSeek's the pack's maximum lowered to fit
  memory; `--max-context` still sets it. [models](../models/index.md)
- **Start lines.** Each model's line shows the drafting the engine will run (`spec=N`); a shared idle sleep is said once, on
  the shared line; the conversation folder line shows only with `--debug`; a load reads `loading MODEL (N waiting)` and a swap
  `swap OLD -> NEW (N waiting)`.
- **DeepSeek's attention caches are FP8 and FP4 by default.** `--kv fp8` rounds them as the model's reference does and
  keeps the codes and scales: 920 bytes per position instead of 3,200, so a 1M context's caches take 0.97 GiB instead of
  3.20. `--kv fp16` keeps the old caches. A conversation stored on disk in the other format is read again from its tokens.
  [precision](../precision/deepseek41.md#where-each-stage-rounds)
- **`--max-payload-mib` sets the largest request body.** The server reads up to 256 MiB by default; a bigger body gets a 413
  naming the limit. [configuration](../configuration/index.md)

## DeepSeek-V4.1-Flash

- **Placement from total RAM.** The choice between main-card homes and copies only reads the machine's RAM (or the container's limit) less the engine's buffers, so the same box starts the same way each time; homes decode about 3.5% faster than copies only. One card keeps homes when RAM cannot take the rest, and the main card grows copies into its spare memory in every arrangement. [DeepSeek-V4.1](../models/deepseek41.md)
- **A 16 GB main card opens the expert tier.** The copies leave the caches of a full context free, not a fixed 6 GiB.
- **cuBLAS is opened at load**, before the tier reads free RAM, so the image encoder's 1.4 GiB of host heap (with `--parallel 2`) no longer comes out of the experts' RAM.
- **Prompt chunks with the second card** compute its own experts in place and a share of the RAM ones over its own link; nothing goes second card, host, main card any more. MMQ tiles load at init, so a long chunk no longer stalls on a first launch. [precision](../precision/deepseek41.md)
- **Decode kernels,** all bitwise the same output: sparse MQA's code size (125 KB to 61 KB), the indexer's top-k in one launch per window and from one block for short sequences, a warp per row in the bf16 gemv, the index key on a cluster of eight blocks, the router ranking only the experts that can make the top-k, the grouped `wo_a`, the routed rows' copy beside the router, the head's branches as graph branches.
- **File experts keep peer moves and homes** on every layer without a swap in flight.
- The UD-IQ1_M pack's expert formats are listed as its layout has them. [model file](../model-file.md#deepseek-pack)

## Flash-Next

- **Packs:** `UD-IQ1_S` converts as shipped (a layer has IQ2_S gate and IQ2_XXS up rows) and `UD-IQ4_XS` is on Hugging Face; the Unsloth UD-IQ1_M, UD-IQ2_XS and UD-IQ3_XXS packs replace the GSQ-RCO ones. [Flash-Next](../models/qwen38-flash-next.md)
- **Experts:** Q5_0 down layers run on MMQ prefill and the device-planned tail; Q2_K and Q3_K tiles, grouped kernels and CPU dots; IQ4_XS and Q5_K/Q6_K gate/up rows join the glue kernel.
- **`--no-peer-prefill`** replaces `--peer-prefill-rows`; the peer card's prompt share runs on the transport DeepSeek uses.

## Fixed

- A dead engine is reported by its exit code or signal and its last error line, not a guessed cause.
- Engine protocol lines are written whole, so a progress line no longer lands inside a token line.
- `/metrics` keeps the last context while a start is under way; the stats page shows a single slot's context.
- The telemetry thread stops when the router stops or the server closes.
- A request with images no longer scans their base64 for literal tags.
- The auto line names the resident amount as `ram-experts`; `--model` with a config file says it is not supported.
