# 0.1.0

2026-10-29. The first tagged release, taken from `main`. Build from source: [building](../building.md).

## Highlights

- Conversations on disk: parked conversations are restored after a restart, a crash or an idle unload; a 100K-token conversation is back in about 0.5 s after a restart instead of a 10 s re-read (5090 at 400 W with a 5060 Ti at 180 W). [running](../running.md#conversations-on-disk---conversation-cache-disk-mib)
- Sleep in place: `--idle-sleep` frees the VRAM between requests, and the next request wakes the model in about 4 s instead of a 40.6 s cold load (same cards and limits). [running](../running.md#sleep---idle-sleep)
- Stats page: one view with a GPUs sidebar, Speed, Slots and Logs. [running](../running.md#the-stats-page)
- Grammar on by default: tool calls and JSON schemas are enforced during decoding. [precision](../precision/features.md#request-grammar)
- Native Windows x64 port, built and CPU-tested in CI on every pull request. [platforms](../platforms.md)
- `basalt-probe`: measures the machine and the cold decode speed and suggests settings. [probe](../probe.md)

## Basalt at 0.1.0

- Model: Qwen3.8-Flash-Next, one `.basalt` file with weights, tokenizer, MTP drafter, expert profile and vision projector. Packs: NVFP4, UD-Q4_K_XL, UD-Q5_K_XL, UD-Q6_K_XL, Q8_0, GSQ-RCO IQ3_S, IQ3_XXS and Q2_0. [model file](../model-file.md)
- Hardware: NVIDIA Blackwell (sm_120) with CUDA 13, on Linux and Windows x64. [platforms](../platforms.md)
- API: OpenAI- and Anthropic-compatible (chat, messages, responses, count_tokens), tool calls, JSON schema output, web UI and stats page. [configuration](../configuration/index.md)
- Expert tiers: experts that miss VRAM live in system RAM, optionally resident; the adaptive tier moves the hot ones into VRAM as a conversation runs. [expert cache](../configuration/index.md#expert-cache-and-memory)
- Peer cards: one `gpu` setting picks the cards; every card after the main one is an expert tier (up to three). [GPUs](../configuration/gpus.md)
- MTP drafting: the pack's drafter proposes up to 8 tokens per window; output equals plain decoding unless relaxed drafting is on. [speculative decoding](../configuration/index.md#speculative-decoding-mtp), [precision](../precision/features.md#speculative-decoding-does-not-change-output)
- Grammar: GBNF and JSON-schema grammars from llama.cpp, on by default, enforced per verify window. [precision](../precision/features.md#request-grammar)
- Vision: image input through the pack's projector, in the engine, on a sidecar card or on the CPU. [running](../running.md#vision---vision)
- Parallel slots: `--parallel N` serves up to 8 requests at once. [running](../running.md#concurrent-requests---parallel-n)
- Conversation cache: checkpoints in RAM, conversations parked on disk and restored after a restart. [running](../running.md#conversations-on-disk---conversation-cache-disk-mib)
- Sleep in place: `--idle-sleep` gives the VRAM back between requests and keeps the process. [running](../running.md#sleep---idle-sleep)
- Prompt path: a long prompt is read across the cards; prefill streams experts under the compute. [GPUs](../configuration/gpus.md#long-prompts-across-the-cards)
- Auto settings: left-out settings are picked at start and printed on one line. [configuration](../configuration/index.md#automatic-settings)
- basalt-probe: measures the machine and the cold decode speed and suggests values. [probe](../probe.md)
- Quality: PPL and KLD against Q8_0 through the decode path. [precision](../precision/index.md)
- Community runs: user benchmark rows on one preset. [community](../community.md)

## Recent

Changes from 2026-10-15 to 2026-10-29.

### New

- `--idle-sleep`: the model sleeps in place between requests and wakes on the next one (Linux).
- Conversations on disk: `--conversation-cache-disk-mib` parks conversations and restores them after a restart or a crash.
- A start places the experts the last run saved with `--expert-profile-save`.
- Three or more alike cards: a long prompt is read across them by default. Up to three expert tiers.
- Prompts of up to 16384 tokens read alone while other slots decode; slots share a prompt's start through each other's checkpoints.
- `basalt-probe`: measures the machine and suggests settings.
- Grammar: GBNF engine, llama.cpp's JSON-schema converter and tool-call grammars; Anthropic `output_config.format` sends the grammar; each batch slot holds its own grammar.
- Tool call parameters are decoded by their declared schema.
- The tokenizer is C++ and the server sends rendered prompt text to the engine.
- `reasoning-budget-tokens` sets the default thinking budget; `answer-room` reserves output space for the answer after thinking.
- Console log: one compact `key=value` line per event; load progress shows off a terminal with a busy heartbeat and MB/s.
- Stats page: one view with a GPU sidebar, Speed, Slots and Logs; `/metrics` carries per-card and per-slot history, the queue and the best requests.
- Windows: native x64 port, CI builds and CPU tests on every pull request.
- Community runs page on GitHub Pages; new rows for RTX 5090, RTX 5080 (WSL2), RTX 5060 Ti and RTX PRO 4000 setups.

### Faster

Numbers are in the commit messages and [precision](../precision/index.md). No figure here is a benchmark result.

- Decode: the next layer's weights are read into L2 while a combine waits for the CPU or peer tier; the GDN layers after the first commit inside the next window; the shared expert runs beside the routed chain.
- Decode on a faster peer card: it takes its key heads of each GDN layer and a share of the head, when the model prices a saving.
- Pool: finer row-range tasks, one batch per layer, AVX-VNNI in the AVX2 i-quant rows; a parked worker yields its core after a short spin. AVX-512 i-quant rows build sign masks with pdep and gather the IQ3_S and IQ2_S grids (same bits).
- Prefill: FP4 experts in groups of 16 for short chunks, the next layer's likely experts copied during attention, a short first chunk on a long prompt.
- Long prompts: read across the main card and every expert tier card.
- A sampled row picks in one launch; the first 8192 token-embedding rows also live in VRAM.
- `qsa`: a window of five to eight queries scores its blocks as two rows of four.
- Q6_K gate/up experts run on their own decode and prefill kernels (prefill on the MMQ kernel); Q8_0 dense projections run on the tensor-core kernels and the mid chain.

### Changed

- `gpu` is the one card setting. Removed: `--peer-device`, `--peer-slots`, `--layer-split`, `--split-device`, `--split-skip-if-fits`, `--batch-groups`, `--expert-cache-device1` to `3` and the stage and remote options that needed them. The layer split is no longer picked.
- Also removed from the engine: `--spec-min-p` (the adaptive draft rule is always on), `--spec-split`, `--no-spec-split`, `--coupled-draft`, `--no-coupled-draft`, `--pcie-frac`, `--pcie-mode`, `--expert-cache-remote-placement`, `--remote-expert-opt`, `--expert-cache-per-layer`, `--expert-cache-cpu-order`, `--trim-stage-weights`, `--sync-every-layer`, `--stream-token`, `--shared-late`, `--ple-sync-submit`, `--no-ple-prefetch`, `--no-host-worker`, `--no-prefill-borrow`, `--no-split-rows`, `--no-hit-poke`, `--no-token-graph`, `--no-publish-kernel`, `--no-fast-attn`, `--no-fast-select`, `--no-fused-gdn`, `--no-fused-gr`, `--gr-fp32-activations`, `--gr-native-mmvf`, `--cpu-oracle-q8-0`, the `--native-*` switches (`bf16`, `bf16-extra`, `flash-attn-short`, `gdn`, `moe-combine`, `ple-key`, `ple-postops`, `qsa`, `qsa-indexer`, `rope`, `router`) and the diagnostic `--dump-logits`, `--dump-layers`, `--dump-halves`, `--check-logits`, `--logits-stride`. Each one was forced on, never read, or chose an old code path; the default path is unchanged.
- `vision` takes `off`, `dynamic`, `cpu` or a GPU number; `on` and `peer` are refused.
- `spec` defaults to 8 with a drafter (was 7). Greedy output is unchanged; a seeded sampled request can return different text.
- Defaults: `prefill` auto; resident experts when the pack has an expert profile; a server on one card adapts every window.
- Grammar is on by default and `response_format` selects it; `--no-grammar` turns it off. The prompted, post-validated JSON path, its `structured_output_failed` errors and the `jsonschema` dependency are gone.
- A request must name the served model (the alias or the file name); an unknown or missing name is a 404.
- A tool name is read exactly as written.
- The CPU pool workers and the host thread no longer pin to single cores; `--pool-affinity` only chooses which cores size the pool.
- The prompt path to a peer card is host-staged only; the direct-access path is gone.
- The model cache directory is no longer set by an environment variable; `--native` and `--pack` are gone.
- Stored conversations are bound to a format version, not to the engine version, so a new build restores what an older one wrote while the format holds. Files written by earlier builds are not restored once.
- An image past 64 megapixels is refused before it is decoded.
- On a hybrid CPU, `pool-affinity auto` adds half the E-cores to the pool.

### Fixed

- Windows: the engine keeps full speed while its window is in the background.
- Windows: the working-set minimum is set as the hard limit, so the expert table can be locked.
- A nullable string tool parameter takes raw text; raw control bytes from a schema pattern reach the grammar as `\xNN` escapes.
- Elastic KV never takes the expert cache below a prompt chunk's loan; a request that cannot fit is refused, not fatal.
- Profiled cache slots are budgeted at their 256-byte aligned size.
- The prompt path's lend cap reads the pinned share once the RAM complement is pinned.
- The live tok/s keeps its 2 s window above 128 tok/s instead of falling back to the mean.
- A request that moves between solo and a slot reports its real prompt-read time.
- A failed expert copy to RAM syncs before its homes are freed.
- `avx_bench` leaves out the AVX-512 rows on a CPU without AVX-512.
- MSVC: the CUDA targets build with `/Zc:preprocessor`; NVFP4 CPU expert rows avoid aggregate copies.
