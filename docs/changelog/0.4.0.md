# 0.4.0

2026-11-14. Taken from `main`. Build from source: [building](../building.md), or take a release archive ([platforms](../platforms.md#release-archives)). A third model and the engine's first dense one. The `.basalt` format stays version 2 (two new tensor types, see Upgrading) and the config stays version 2.

## Highlights

- **Qwen3.8-27B**, Basalt's first dense model, from NVIDIA's NVFP4 checkpoint with the DFlash 2 block drafter. One card, chat, tools, thinking, images and video, up to 262,144 tokens of context. [guide](../models/qwen38-27b.md)
- Speed on one RTX 5090 at 400 W, `--kv fp16`, cold (`basalt-bench`): prompt reads 10,727 tok/s at 4k tokens and 7,708 tok/s at 32k; decode 78 tok/s plain and 204 tok/s drafted (conversation), 700 on struct.
- Drafting in windows of up to 16 rows, with prompt lookup (`--suffix-draft`) beside the drafter, and `--parallel` slots that share one pass through the weights each round.
- Checkpoints of every model's conversation state go through one shared, page-locked transfer.
- A thinking budget stops the engine on its last token, so the answer continues the engine's own state.

## Qwen3.8-27B

- **Pack.** `convert.py --checkpoint nvidia --drafter dflash2` builds it from two downloads, about 20 GiB (22 GiB with the drafter). The MLP and output head keep NVIDIA's NVFP4 bit for bit (`NVFP4_PLANES`, tensor type 45), the GDN and attention projections their FP8 codes (`F8_E4M3`, type 44). [model file](../model-file.md#qwen38-27b-pack)
- **Prompt reads** run W8A8 on the FP8 tensor cores for the projections and W4A4 on the FP4 tensor cores for the MLP at every chunk length, in chunks of 4,096 tokens, on TMA tile pipelines adapted from Infernix. The residual stream and activations are BF16. Int8 KV prompt attention reads 8-bit P V.
- **Decode windows** run their products on one kernel that reads each FP8 or NVFP4 matrix once for up to 16 rows, with attention on the tensor cores. A row's arithmetic does not depend on the window, so greedy output with drafting is bitwise plain greedy, alone or beside other slots.
- **Drafting.** The DFlash 2 block drafter's block of 8 rows widens after windows whose drafts were all kept; the draft policy reads each draft's confidence to pick the window. `--spec` defaults to 16. Without the block drafter the pack's MTP layer drafts.
- **Memory.** `--kv fp16` (default) or `int8`. `--parallel N` gives each slot its own cache and recurrent state. `--vision dynamic` for pictures and video. [guide](../models/qwen38-27b.md#memory)
- **Quality** against the BF16 model, 100 chunks, `--kv fp16`: PPL 6.7843 against 6.7411 for the base on the same rows, mean KLD 0.0239, top-1 92.52%; `--kv int8` 6.7814, 0.0240 and 92.56%. [precision](../precision/qwen38-27b.md)

## Shared engine

- **A dense stack** (`src/dense`) runs hybrid GDN and gated attention layers with a dense FFN from a pack's widths; a model of that family needs only its pack read in. [adding a model](../adding-a-model.md)
- **GDN kernels are shared** by Flash-Next and the dense stack, and so are the Qwen pre-tokenizer, the tool-call form and the Qwen serve dialect (`serve/models/qwen.py`). Flash-Next keeps its 8-row verify window and its output.
- **Slots of a round run as one batch** when the model batches its sessions, and start their drafts as one pass (`draft_batch`).
- **Checkpoints** take their running state as device regions the model lists; the engine copies them through page-locked blocks it holds from start, and a save reaches the host while the request goes on. DeepSeek and the 27B use the same path as Flash-Next did.
- **Images and video** take the encoder's grid through the session; a model that reads the shared preprocessor's patches (the 27B) gets video from the server.
- **Thinking budget.** The first pass asks for the budget's tokens only, so the engine stops on its last one and the answer continues its state instead of reading the overshoot again through the prompt path.
- CI builds `qwen35` as a single-model build too, beside `qwen4exp` and `deepseek41`.

## Fixes and platforms

- DeepSeek: with experts left in the file, the RAM tier now caches each file expert a lookup routes to, read whole off the file cache, instead of the CPU computing it from the mapped pack a page fault at a time (#318, @mitalbert).
- A `--resident-budget-gib` that holds every expert no GPU tier holds keeps the prompt path's lend region, so a prompt read beside decoding slots keeps its full chunks (#329, @gdevenyi).
- Windows: the expert RAM is backed by a host VMM allocation where CUDA host registration fails under WDDM (#297), and positional reads run concurrently on unbuffered handles (#296), both by @LesterLyu.
- Image and video encodes write their scratch files per attempt, and a scratch file the encoder still holds no longer fails the request (#302, @easonLiangWorldedtech).
- Community rows from @changlv (#335, #340) and @huangwb68 (#336).

## Upgrading

- **`.basalt` tensor types 44 (`F8_E4M3`) and 45 (`NVFP4_PLANES`)** appear in Qwen3.8-27B packs; no version change. An engine from before refuses such a pack by tensor name. [file changelog](../basalt-file-changelog.md)
- **Build a 27B pack with this release's converter.** The engine refuses a 27B pack whose MLP is NVFP4 in ggml blocks and asks for a re-conversion.
- **`-DBASALT_MODELS`** takes `qwen35` as well; the default builds all three.
- **Conversation checkpoints take page-locked RAM from start** (`--prompt-cache` plus one per slot): the start reserves them before it sizes the RAM tier. A conversation parked to disk by an older build whose running state had another size is read again, not mounted.
- **A thinking budget** now stops the engine pass at the budget (all models).
- No flag or config key is removed or renamed. The `.basalt` format stays version 2 and the config version stays 2.

## Checked

At 400 W + 180 W, on the release commit against 0.3.3's `main` where a model's output could move:

- Flash-Next and DeepSeek greedy output on frozen tiers: identical to 0.3.3's `main` (Flash-Next: conv, struct and prose, 300 tokens each, `--kv int8`; DeepSeek: 128 tokens each with the RAM tier pinned; both on two cards), and DeepSeek's start plan and tier placement unchanged.
- Qwen3.8-27B: greedy output with drafting is plain greedy's, and two slots, alone or on different prompts, give each slot's solo text (conversation, prose, 8k and 16k prompts; 32 prompt-set texts in pairs).
- Parity tests for every new kernel, against the CPU reference and the kernel it replaces: pass (`dense_ops`, `gqa_attn`, `window_gemm`, `gdn_seg_split`, `fp8_gemm`, `fp4_dense_tma`, `e4m3_producers`, `bf16_chunk`, `silu`), and Flash-Next's GDN kernels stay bitwise (`dec_gdn`, `gdn_head_split`, `mid_chain`).
- Quality gate for the 27B, 100 chunks: see Highlights.
